## 骨架：一块画布，七张图纸，一个场景时间

页面最底层是一块铺满屏幕的 `<Canvas>`，所有 3D 都画在这里；文字、面板、HUD 是普通 DOM，叠在上面。

首页由七张「图纸」组成：你好、关于我、技能、项目、经历、文章、联系。每张图纸是一个很高的 `<section>`，高度是若干个屏幕；里面的内容是 `position: sticky; top: 0`，在这张图纸滚过的时候一直钉在屏幕上。所以图纸有多高，这一幕就演多久：一张 4 屏高的图纸，内容会在屏幕上停留 3 屏的滚动距离，最后一屏被下一张推走。

3D 那边从来不直接看滚动条，而是看一个叫**场景时间**的数 `s`：

```ts
// 第 i 张图纸从 top 开始，高 height：滚到 y 时
s = i + (y - top) / height
// 0 = 首页顶端，1 = 「关于我」开始，2.5 = 技能滚到一半
```

镜头、每一幕的出场退场、明暗切换、该显示哪张卡片，全部只读这一个数。这样 DOM 和 3D 永远不会对不上；想让某一幕演久一点，只要改那张图纸的高度，3D 那边一行都不用动。

## 渲染：一种材质，一张 G-buffer，一个把它「画」出来的 pass

网站想要的是「画出来」的样子：有墨线勾边，暗的地方是网点和排线，像印在纸上。墨线是这里的难点。一条轮廓线的位置，取决于这个像素和**旁边的像素**是不是同一个物体、离镜头是不是一样远；可是普通的着色器一次只能看到自己正在画的那一个像素。

所以渲染拆成两步，这种做法叫延迟渲染（deferred rendering）：

1. 先把场景画一遍，但不画颜色，而是把每个像素「是什么」写进几张贴图，这几张贴图合起来叫 **G-buffer**；
2. 再用一个铺满屏幕的着色器读这几张贴图。这时候每个像素想看哪个邻居都可以，墨线、网点、排线都在这一步「画」出来。

<Figure n="02" caption="一帧画面经过的五步。③ 是整个网站最核心的着色器。">
  <PipelineDiagram lang="zh" />
</Figure>

网站里几乎所有 3D 物体都用同一种材质。它不输出颜色，而是用 WebGL2 的多渲染目标（MRT），一次往两张贴图里写数据：

```glsl
layout(location = 0) out vec4 gColor;   // 明暗、是否强调色、填充方式
layout(location = 1) out vec4 gNormal;  // 视空间法线 + 物体 id

float halfLambert = dot(n, lightDir) * 0.5 + 0.5;
float tone = clamp(pow(halfLambert, 1.35) + uToneBias, 0.0, 1.0);
gColor  = vec4(tone, accent, uFill, 1.0);
gNormal = vec4(n * 0.5 + 0.5, uObjectId);
```

明暗用的是**半兰伯特**：普通兰伯特光照 `dot(n, l)` 在背光面会一路掉到负数、全黑；乘 0.5 再加 0.5 以后，背光面也保留一点层次，正适合用网点去表现。光从左上方来，这是画画时约定俗成的光源方向。每个材质创建时分到一个编号，就是物体 id。

### 墨线：每个像素和 8 个邻居比

合成着色器对每个像素做同一件事：拿它和周围 8 个方向、距离 1 个 CSS 像素的邻居比较，看两者之间有没有「断开」。一共有四种断开：

- **轮廓**：一个有东西、一个没东西（`gColor.a` 不同）。
- **物体 id**：两个都有东西，但不是同一个物体。
- **折痕**：法线夹角大。`1 - dot(n, n0)` 在两个面平行时是 0，垂直时是 1，取 0.3 到 0.7 之间平滑过渡，大约就是「夹角超过 45° 开始画线」。立方体的棱就是这样画出来的。
- **深度**：前后差得多。这里用的是**相对**深度差 `|d - d0| / min(d, d0)`，不是绝对差。远处的地板，每个像素之间本来就隔着很长的距离；如果用绝对差，远处的地板会被画满线，近处真正的断开反而可能不够格。除以距离以后，远近一视同仁。

四种测试取最大值，就是这个像素的墨线浓度。轮廓还会在 1.8 像素远的地方再比一次，所以外轮廓比内部的线粗一点，像画画时外轮廓下笔更重。

```glsl
float edgeSample(vec2 uv, vec4 c0, vec4 n0, float d0) {
  vec4 c = texture(tColor, uv);
  vec4 n = texture(tNormal, uv);
  float d = linearDepth(texture(tDepth, uv).r);
  float both = c.a * c0.a;
  float silhouette = abs(c.a - c0.a);
  float idEdge = step(0.003, abs(n.a - n0.a)) * both;
  float crease = (1.0 - dot(n.xyz * 2.0 - 1.0, n0.xyz * 2.0 - 1.0)) * both;
  float depthEdge = abs(d - d0) / max(min(d, d0), 0.001) * both;
  return max(max(silhouette, idEdge),
             max(smoothstep(0.3, 0.7, crease), smoothstep(0.015, 0.04, depthEdge)));
}
```

它和常见的 Sobel 算子是近亲。Sobel 用一个 3×3 的加权核去算梯度，适合连续变化的量；这里直接取「和邻居的最大差别」，线更干脆，而且物体 id 这种「是不是同一个」的类别数据本来就没法求梯度。

### 网点和排线：用墨的多少表示明暗

印刷品里没有灰色的墨，灰是用大小不同的黑点「骗」出来的：远看时，眼睛把一小块区域里墨的比例当成了灰度。网站的网点也是这个原理：

- 在屏幕上铺一张 5×5 像素的格子，转 45°。45° 是印刷里黑版的传统角度，横平竖直的网格最容易被眼睛看出来。
- 每个格子中间画一个圆点。点的**面积**要和暗度成正比，而面积和半径的平方成正比，所以半径取暗度的平方根。
- 暗度低于 0.22 的地方一个点都不画，亮面保持干净的纸色。

```glsl
float halftone(vec2 sp, float darkness) {
  vec2 p = rot(0.785398) * sp;           // 转 45°
  vec2 g = fract(p / 5.0) - 0.5;         // 在 5px 格子里的位置
  float r = sqrt(clamp((darkness - 0.22) / 0.78, 0.0, 1.0)) * 0.6;
  return 1.0 - smoothstep(r - 0.12, r + 0.12, length(g));
}
```

再暗的地方叠排线：间距 4.5 像素，第一层 +45°，暗度到 0.55 开始出现；第二层 −45°，到 0.78 开始出现，交叉成网。线宽随暗度慢慢变粗，不会一下子冒出来。

网点和排线都是在**屏幕空间**里算的（用的是像素坐标，不是物体表面的坐标），所以物体放大缩小，网点的疏密都不变，就像真的印在纸上，而不是画在物体身上。

### 纸、墨和对调

每个表面还有一个「填充方式」：

| 填充 | 怎么画 |
| --- | --- |
| 着色（shaded） | 上面那套网点和排线 |
| 纸（paper） | 平涂，明暗表示印上去的墨有多少 |
| 真纸（sheet） | 和纸一样，但**不跟着反色** |
| 墨（ink） | 实心墨色 |

亮场和暗场是同一个着色器：纸色和墨色由一个 `uInvert` 在 0 和 1 之间插值，切换时花大约 0.8 秒慢慢过渡。「真纸」不参与对调，所以撕碎的图纸在暗场里依然是一张张纸。

合成之后还有一层镜头效果：色差、CRT 桶形畸变和扫描线、高速滚动时从消失点放射出的速度线、点击空白处的墨水冲击波、暗角。墨线还会随时间轻微地、连续地晃动，像手画的线；最早是一秒 12 次的「抖动」，看起来像卡顿，后来改成了平滑的噪声。

有一条硬规矩：**不闪屏**。整屏闪白会让光敏性癫痫的人很难受，所以切镜只用轻微的推镜和一小段故障条纹，从来没有全屏闪烁；系统开了「减少动态效果」时，这些效果全部关掉。

### 清晰度

手机屏幕的像素密度是 3 倍，画布如果只按 1 倍渲染，3D 文字会糊成一片。现在画布按**像素预算**决定倍率：总像素大约 320 万封顶，所以手机能用 2 倍，大显示器少一些。设备跑不动时（drei 的 `PerformanceMonitor` 报告掉帧），只降一次，降四分之一，避免滚动到一半反复重建画布。

经历里的路牌是贴在 3D 场景里的 DOM（CSS 3D 变换）。WebKit 按元素的布局尺寸把它栅格化成一张图，再交给 GPU 去变换；字排得小、再被变换放大，就会发虚。所以这些元素先按 2 倍尺寸排版，再让变换缩小一半。

## 开场：170 块碎片，一次绘制调用

开场那张图纸，其实是 170 块碎片严丝合缝拼起来的。

碎片的形状来自 **Voronoi 图**：在平面上撒一些种子点，每个种子「占领」离它比离其他种子都近的那片区域。这些区域天然地把平面铺满，不留缝也不重叠，边界又是不规则的多边形，很像真实材料裂开的样子。计算用的是 d3-delaunay：先算种子点的 Delaunay 三角剖分，Voronoi 图就是它的对偶。

种子不是均匀撒的。45% 的种子聚在 QwQ 的脸周围，离脸的距离按 `sqrt(-2 ln u) · σ` 抽样，这正是二维正态分布的半径分布（瑞利分布）；剩下的均匀撒满整张纸。结果是裂口附近碎得细，越往外碎片越大。

每块多边形挤出一点厚度，变成一块有正面、背面和侧壁的薄片。170 块薄片要是做成 170 个物体，就是 170 次绘制调用，每帧还要分别更新它们的位置。这里把所有碎片**合并成一个几何体**，每个顶点额外带三样东西，让顶点着色器自己去算每块碎片该在哪：

- `aCenter`：所在碎片的中心；
- `aRand`：三个随机数，决定翻转轴、转几圈、飞多远；
- `aDelay`：碎片中心到裂口的距离，除以最大距离，再加一点随机，范围 0 到 1。

整张纸只有一个全局的 `uBreak`，随滚动从 0 涨到 1.7：

```glsl
float local = uBreak - aDelay * 0.6;      // 这块碎片「轮到」多久了
if (local > 0.0) {                         // 没轮到的一个字节都不动
  float lift = smoothstep(0.0, 0.12, local);
  float t = clamp((local - 0.06) / 0.5, 0.0, 1.0);
  float e = t * t;                         // 先慢后快
  vec3 axis = normalize(aRand - 0.5 + vec3(0.0, 0.0, 0.001));
  mat3 R = rotateAxis(axis, e * (2.5 + aRand.x * 5.0));
  pos = aCenter + R * (pos - aCenter);     // 绕自己的中心翻转
  nrm = R * nrm;
  vec3 away = normalize(vec3(aCenter.xy * 0.25, 1.0));
  pos += away * e * (16.0 + aRand.y * 18.0);  // 朝镜头、略微往外飞
}
```

逐行看：

- `local` 是关键：离裂口近的碎片 `aDelay` 小，先变成正数，所以洞从脸开始，一圈一圈往外扩。
- `lift` 让碎片先微微抬起、错开，`e = t²` 让它先慢后快地翻转、飞走，像被什么东西从后面顶破。
- 翻转轴来自随机数，每块碎片各翻各的；`rotateAxis` 是绕任意轴旋转的罗德里格斯公式。
- 飞行方向主要朝镜头（z），再按碎片所在位置往外偏一点，于是碎片会从画面中心向四周炸开。

那个 `if` 很重要：还没碎的部分一个字节都不能动。哪怕只是先乘一个单位矩阵再乘回来，浮点误差都会让相邻碎片之间漏出一条条细缝。

## QwQ：一个颜文字做的吉祥物

QwQ 的五官全是程序生成的几何体。笔画是沿着一条曲线生成的管子（`TubeGeometry`），两头再各补一个小球当笔触的端头，看起来就像一笔画出来的线。眼睛是一个圆环加一条尾巴，所以是 Q；里面的瞳孔会跟着鼠标看。

每种表情就是「哪些部件显示」的一份清单。切换表情时，部件不会直接出现或消失，而是由一个带阻尼的弹簧把缩放从 0 拉到 1，带一点回弹，看起来像「蹦」出来的：

```ts
// 每帧：弹簧往目标值拉，阻尼让它停下来
velocity += ((target - value) * k - velocity * c) * dt;
value += velocity * dt;
```

表情由一个小「大脑」按优先级决定：鼠标离开窗口 > 被戳哭了 > 晕了 > 被戳 > 被悬停 > 睡着 > 这一幕的默认表情。`QAQ` 会撇着嘴、皱着八字眉、抬头看你，眼泪从两只眼睛下面轮流冒出来，滑一小段就淡掉。

## 镜头：关键帧，和一条不会冲过头的曲线

镜头是一串关键帧：在某个场景时间，镜头站在哪、看向哪、歪多少度。两个关键帧之间要补出平滑的路径，常用的办法是**三次 Hermite 插值**：已知两端的值和两端的切线（也就是速度），中间用一个三次多项式连起来。

问题在于切线怎么定。最常见的 **Catmull-Rom** 样条，把每个关键帧的切线取成「前一个和后一个关键帧之间的斜率」。镜头停靠的地方是两个值相同的关键帧（同一个位置，停一会儿），可是它们的邻居不同，切线就不是 0，曲线会在两个相同的关键帧之间先冲出去、再拐回来：镜头在本该停住的地方晃一下。

网站用的是 **Fritsch–Carlson 单调三次样条**。它保证「关键帧之间单调的地方，曲线也单调」，做法是修正切线：

1. 两个相邻关键帧的值相同（停靠），这一段两端的切线都设为 0：镜头真的停住。
2. 如果左右两段的斜率方向相反（这是一个峰或谷），切线设为 0：不会冲过峰顶。
3. 切线和这一段平均斜率的比值 `α`、`β` 要满足 `α² + β² ≤ 9`，超了就按比例缩回去：这是不超调的充分条件。

```ts
if (d[i] === 0) { m[i] = 0; m[i + 1] = 0; continue; }   // 停靠：真的停住
const a = m[i] / d[i], b = m[i + 1] / d[i];
const h = Math.hypot(a, b);
if (h > 3) { m[i] = (3 / h) * a * d[i]; m[i + 1] = (3 / h) * b * d[i]; }
```

在关键帧之上，导演还叠了几层「手持感」：鼠标位置会轻轻带动镜头；滚得越快，视角越广，最多宽 6°；每次切镜有一个缓慢的推镜。手机竖屏用另一套关键帧，比如项目屏幕在手机上几乎正对镜头，并后退到能装下整块屏幕的距离。

点右上角的「全景」，镜头会拉到高空，整条飞行路线和每一幕的布景变成一张 3D 地图，点任何一幕就飞过去。

## 滚动：前半段一拍一拍，后半段一路到底

这是改动最多的一块。最初是普通的平滑滚动，结果滚轮一转好几圈、手机猛地一甩，技能和项目就一闪而过，什么都没看清。现在滚动分成两段。

### 前半段：逐拍吸附

首页、撕纸后的玩具、关于我、地图、每一张技能卡、每一块项目屏幕，各是一「拍」。Lenis 提供一个 `virtualScroll` 钩子，可以在它处理滚轮和触摸之前把事件截下来；在首页，我在这里接管滚动：

1. **一次手势只走一拍。** 滚轮事件之间安静超过 180 毫秒，就算一次新手势。一次手势一旦让页面走了一拍，它剩下的事件，比如滚轮连转好几圈、触控板甩出去以后那一长串越来越小的惯性事件，都会被吞掉。
2. **怎么分辨「惯性」和「又推了一把」？** 惯性事件的滚动量是单调衰减的；如果在衰减到峰值一半以下之后，又突然出现比最低值大 2.5 倍的事件，那就是手指又推了一下，算新手势。
3. **要推够才走。** 每次滚动先累积成「拉力」，画面朝下一拍探出去一点：探出的距离是 `room · (1 − e^(−0.5·拉力/room))`，一开始跟手，越拉越吃力，最多探出两拍间距的 40%。拉力累积到大约四分之一屏（160 到 300 像素，普通鼠标滚轮约三格）才真正滑过去；停手超过 0.42 秒还不够，就弹回原位。
4. **滑行时长固定，不看你推得多猛。** 时长按距离算，`0.55 + 0.5 × 屏数` 秒，夹在 0.85 到 1.6 秒之间，缓入缓出。滑到一半又来一次手势，会排队等这一拍落稳再走。

  <BeatLab lang="zh" />
</Figure>

手机上没有滚轮事件，而是直接拦截 `touchmove`，阻止浏览器自己的滚动，再看手指拖了多远、多快：拖过屏幕高度的十分之一，或者快甩（速度超过每毫秒 0.5 像素、距离超过屏幕的 6%），才翻一拍，否则弹回。键盘的方向键、空格、PageUp/PageDown 也是一次一拍。

### 后半段：连续滚动

经历是一条路，适合一路骑下去，而不是走一步停一步。所以从经历的第一个节点开始，一直到页尾，都是平滑的连续滚动：滚轮滚多少走多少，手机上手指拖着走，松手按速度带一段惯性滑行。

镜头这一段也不再有停靠的关键帧，每个节点只有一个关键帧，相邻节点间距相同，所以匀速滚动时镜头也是匀速前进，只在经过路牌时转头看一眼。城市俯瞰的那一段，镜头也保持缓慢上升，不会停住。

只有一个例外：从经历那边猛甩过来，会在文章这一拍被接住、减速停下，不会一下冲到页尾。往回滚到经历开头也会停住，再往上才回到逐拍吸附。

### 一个和 sticky 有关的坑

面板里的文字是一行一行「打」出来的。最初用 GSAP 的 ScrollTrigger：它在页面加载时量好每个元素在页面上的位置，滚过那个位置就播放动画。可是面板放在 sticky 容器里，它在屏幕上的位置会随滚动变化，预先量的位置和屏幕上实际看到的对不上，来回滚几次，「关于我」的卡片就空了。现在每次滚动都直接看面板此刻在屏幕上的实际位置：露出超过 15% 就打字，整个掉到屏幕下方才收起来。

## 各幕的细节

**关于我。** 一段写成 TypeScript 的自我介绍，`init(me);` 这几个字是从平面上跳出来的 3D 挤出字。3D 字用的是 Archivo Condensed 和 JetBrains Mono，事先转成 three.js 能读的 typeface JSON。中文只走 DOM，用系统字体：中文网络字体动辄几 MB，Google Fonts 在国内也打不开。

**足迹地图。** 镜头转过去俯看一张中国地图。原始数据来自阿里云 DataV GeoAtlas，边界点非常密，直接用的话文件有好几 MB。这里用 **Douglas–Peucker 算法**来简化：

1. 连接一段边界的首尾两点，得到一条弦；
2. 找出这一段里离弦最远的点；
3. 如果它离弦超过容差，说明这里有重要的弯折，把它留下，然后从它这里拆成两段，分别重复；
4. 如果没超过，这一段中间的点全都可以扔掉。

容差设在大约 0.04 度（岛屿和九段线留得更细），整张地图最后只有 108KB。每个省级行政区单独挤出成一块，去过的升高、染成朱红，每个去过的地方插一根针。手机屏幕小，只插针不挂地名，地方再多也不会挤成一团。

**技能。** 每组技能是路边的一个站台，挤出字一个个飞进来锁住；左边的物料清单（BOM）同步高亮当前这一组。

**项目。** 镜头在一排巨大的屏幕之间穿行。屏幕的脸是一个着色器：扫描线、一条慢慢滚过的亮带，鼠标悬停时噪点带变多。

**经历。** 一条蜿蜒的公路，每个节点是一块路牌。一只骑自行车的鹈鹕在镜头前面 13 个单位处骑行，车轮按镜头走过的距离转（转角 = 距离 / 车轮半径），往回滚它就掉头。公路尽头是一座 GitHub 城市：近一年每天的贡献数变成一栋楼，用实例化渲染一次画完；镜头先在楼群脚下仰视，再升到高空，整年读起来就是熟悉的贡献格子。数据不用 token，直接解析 GitHub 公开主页上的贡献日历，8 秒拿不到就用仓库里的快照。

**年度回顾。** 经历里有一个「播放年度回顾」的按钮，弹出的是用 Remotion 写的一段视频：七个场景，30 帧每秒，共 1070 帧，大约 36 秒，用 `@remotion/player` 在浏览器里实时渲染，没有预渲染的视频文件。

**文章和联系。** 文章是一排悬浮的纸页；到了联系，碎片飞回来拼成纸，世界回到亮场，QwQ 变成 `^w^` 挥手。

## 交互和彩蛋

- **终端**：按 `` ` `` 或 `⌘K` 打开，支持 Tab 补全和上下键翻历史。命令有 `help`、`ls`、`cd`、`cat`、`now`、`contact`、`projects`、`open`、`blog`、`read`、`lab`、`whoami`、`neofetch`、`date`、`echo`、`history`、`lang`、`qwq`、`gbuffer`、`debug`、`clear`、`exit`。`gbuffer` 就是图 03 里那些分层，在整个网站上实时显示；`sudo rm -rf /` 会让网站「崩溃」，然后重新开机。
- **Debug 打虫**：低多边形的 bug 从纵深飞向镜头，点它就碎。60 秒、3 条命，连击加分，最高分存在 `localStorage`，QwQ 在角落给你加油或者哭。
- **Konami 秘籍**：↑↑↓↓←→←→BA，全场派对。
- **实验室**：两个可以玩的 GPU 小实验。一个是墨水流体：标准的稳定流体（stable fluids）解法，每帧平流、加力，再用 20 次 Jacobi 迭代解压力，把速度场修正成无散度的；另一个是 Gray–Scott 反应扩散，两种「化学物质」互相吞噬、扩散，长出珊瑚和斑点一样的花纹。
- **声音**：全部用 WebAudio 现场合成，没有一个音频文件：撕纸声、切镜的呼啸、键帽的咔嗒、冲击波的闷响、打虫的音效，还有一个随滚动速度开合滤波器的环境音。默认静音，你的选择会被记住。

## Next.js 16 那一侧

- **路由和双语**：每个页面都在 `/[locale]` 下。Next 16 把 middleware 改名叫 `proxy.ts`，我在里面做两件事：按 `Accept-Language` 把访客送到 `/zh` 或 `/en`，以及把 `www.qwq.my` 301 到主域名。
- **缓存**：开了 `cacheComponents`，读文章、读 GitHub 数据的函数标了 `"use cache"`；首页大部分是静态的，少量动态内容流式补上（Partial Prerendering）。
- **文章**：每篇文章一个文件夹，`zh.mdx` 和 `en.mdx` 至少写一个，缺的语言自动回退到另一种。代码高亮在服务端用 Shiki 做好；这篇里的交互图是 MDX 里直接写的 React 组件。还有 RSS（`/zh/feed.xml`）和自动生成的分享图。
- **读文章的时候**，3D 世界不会消失：纸面铺满，QwQ 缩到角落陪你读。

## 部署

网站跑在一台自己的服务器上，用 Docker：

- 三阶段构建（装依赖、构建、运行），基础镜像 `node:22-alpine`，Next 输出 `standalone`（只带运行需要的文件），最终镜像约 230MB；
- `docker compose` 里两个服务：`web` 是网站本身，**不向宿主机暴露任何端口**；`tunnel` 是 cloudflared，在 Docker 内网里直接连 `web:3000`。

<Figure n="14" caption="访问只能走 Cloudflare Tunnel：隧道是服务器主动连出去的，服务器不需要开任何入站端口，DNS 里也只有 Cloudflare 的 IP。">
  <DeployDiagram lang="zh" />
</Figure>

```yaml
services:
  web:
    build: .
    restart: unless-stopped
  tunnel:
    image: cloudflare/cloudflared:latest
    depends_on: { web: { condition: service_healthy } }
    command: ["tunnel", "run", "${TUNNEL_ID}"]
    environment:
      TUNNEL_URL: http://web:3000
```

普通的做法是给服务器开 443 端口，再把域名解析到服务器 IP，这样谁都能查到 IP、直接打到服务器上。隧道反过来：服务器上的 cloudflared 主动和 Cloudflare 建立几条长连接，访客的请求从 Cloudflare 顺着这几条连接送进来。服务器连不上 GitHub，部署就是把代码同步过去，`docker compose up -d --build`。
